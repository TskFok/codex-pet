# 桌宠动画包格式

应用的动画包由 UTF-8 编码的 `pet.json` 和一张静态 PNG 或 WebP 图集组成。旧包导入时生成应用格式第 1 版清单，并逐字节复制图集为 `atlas.png` 或 `atlas.webp`。内部版本与 Codex 旧图集的布局版本独立。

## 第 1 版清单

```json
{
  "version": 1,
  "id": "example-pet",
  "name": "示例桌宠",
  "atlas": {
    "path": "atlas.webp",
    "width": 384,
    "height": 208,
    "cellWidth": 192,
    "cellHeight": 208
  },
  "animations": {
    "idle": {
      "frames": [
        {"rect": {"x": 0, "y": 0, "width": 192, "height": 208}, "durationMs": 280},
        {"rect": {"x": 192, "y": 0, "width": 192, "height": 208}, "durationMs": 110}
      ],
      "loopStart": 0
    }
  }
}
```

- `id` 是跨平台文件名可用的单段标识，`name` 是非空显示名称。
- `atlas.path` 是包内相对路径，扩展名为 `.png` 或 `.webp`，可用 `/` 分隔子目录。路径各段须为跨平台可用的文件名。绝对路径、`.`、`..`、反斜杠、Windows 设备名、备用数据流、链接和重解析点都会被拒绝。
- `atlas.width`、`atlas.height`、`atlas.cellWidth` 和 `atlas.cellHeight` 使用正整数像素。图集大小须与实际解码尺寸一致，格子大小须在图集内。清单和图集各自最多 20 MiB，图集宽高各自最多 4096 像素。
- `animations` 是按动作名称索引的非空对象。每个动作有至少一帧，帧按数组顺序播放。帧使用显式矩形，可跨行排列，也可使用不同于格子大小的矩形。矩形以图集左上角为原点，右、下边界分别可等于图集宽、高。
- `durationMs` 是正整数毫秒。`loopStart` 是可选的零基帧索引。首次播到末帧后，循环从该索引开始。字段省略时动作播放一次，之后保持末帧，直到上层切换动作。
- 可选的 `lookDirections` 是 16 个静态矩形，从正北开始顺时针排列，间隔 22.5°，索引 8 为正南。它们独立于普通动作。没有方向素材时省略该字段。

Rust 的 `pet_core::pet_package::load_pet` 从动画包目录读取并校验清单和图集。桌面前端的 `apps/desktop/src/types.ts` 定义对应的 JSON 类型。

## 旧包映射

源目录的 `pet.json` 使用 `id`、`displayName` 和 `spritesheetPath`。`displayName` 复制为 `name`。应用清单只保留对应上述字段的信息，旧包描述留在原始清单。缺省的 `spriteVersionNumber` 按 1 处理，显式支持 1 和 2。两个布局都是 8 列，每格 192×208 像素。v1 图集为 1536×1872，v2 为 1536×2288。

| 行索引 | 动作 | 帧时长（毫秒） | 播放 |
| --- | --- | --- | --- |
| 0 | `idle` | 280、110、110、140、140、320 | 从第 0 帧循环 |
| 1 | `running-right` | 前 7 帧各 120，末帧 220 | 从第 0 帧循环 |
| 2 | `running-left` | 前 7 帧各 120，末帧 220 | 从第 0 帧循环 |
| 3 | `waving` | 前 3 帧各 140，末帧 280 | 一次 |
| 4 | `jumping` | 前 4 帧各 140，末帧 280 | 一次 |
| 5 | `failed` | 前 7 帧各 140，末帧 240 | 一次 |
| 6 | `waiting` | 前 5 帧各 150，末帧 260 | 从第 0 帧循环 |
| 7 | `running` | 前 5 帧各 120，末帧 220 | 从第 0 帧循环 |
| 8 | `review` | 前 5 帧各 150，末帧 280 | 从第 0 帧循环 |

待机一轮是 1100 毫秒。v2 的第 9 和第 10 行按顺序对应 `lookDirections` 的 16 个索引。

## 安装与重试

调用 `import_pet(source, destination)` 时，`destination` 是最终包目录，通常为 `AppPaths::pets` 下一个全新的子目录。导入先校验源清单、路径和图集内容，再在目标的父目录中创建私有暂存目录。两个文件写入并同步后，以原子操作发布目录。目标已存在时返回错误并保留其中内容。发布前失败可以使用同一目标重试。若发布完成后同步父目录失败，调用方可使用 `load_pet` 确认已发布的完整包。

应用素材存放在应用数据目录的 `pets/` 内，历史日志的清空仅影响历史数据。直接从内部包重新加载时，图集从该包的相对路径读取。
