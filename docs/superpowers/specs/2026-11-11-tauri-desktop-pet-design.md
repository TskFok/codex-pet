# Tauri 双平台独立桌宠设计

日期：2026-11-11。状态：独立实施者审阅已完成，用户已要求据此编写实现计划。设计与计划不代表接入或性能已经验证。

## 1. 目的与确认范围

制作可独立运行的桌面宠物，统一承接 Codex、官方 DeepSeek Harness 的任务提醒，点击提醒返回对应会话。桌宠拥有自己的动画时间轴，解除现有 Codex 播放节奏对素材的限制。

用户已确认：

- macOS 和 Windows 同步支持。
- 使用 Tauri。
- 第一版提供提醒与会话跳转；任务回答、批准、执行控制不在本版范围。

以下是本设计提出的默认决策，尚非用户逐项指定：

- Tauri 2、Rust 后端、TypeScript 与 Canvas 2D；设置界面使用轻量组件，具体前端组件库交由实施者选择。
- 首版验收目标为 macOS 13+（Apple Silicon、Intel）及 Windows 10 22H2 / Windows 11 x64。Windows ARM64 暂不作为首版发布目标。
- 先覆盖同一台电脑、同一登录用户下的原生桌面程序和本地 CLI 会话。WSL、SSH、容器及云端会话需要额外转发，暂不作为已支持环境宣传。
- 首版导入现有宠物包，使用一个桌宠汇总多个来源、多个会话；中文界面，预留本地化结构。
- 默认手动启动、30 FPS 绘制，可切换 60 FPS；开机启动可选。首版先提供个人使用的安装包，不接自动更新服务或应用商店。

## 2. 验证依据与主要限制

当前仓库保存宠物资源，没有可延用的应用工程。已有 Codex v1/v2 图集可以复用；每个动作通常只有 4～8 个独立姿态。提高绘制频率可改善移动和交互，角色姿态更细腻仍需补充素材。

本机 Codex 独立 CLI 0.145.0、桌面内置 CLI 0.167.0-alpha.3.2 均显示 Hooks 已启用。官方 Hooks 提供提交、审批、停止、中断等事件，但仍需用真实的桌面会话和 CLI 会话验证触发范围。`Stop` 表示模型本轮停止，不等价于用户目标达成或任务成功；单个工具失败也不等于整个任务失败。

本机官方 Harness 0.2.2-rc.1 源码具有会话事件、运行状态、审批和用户提问接口，可以使用插件观察。当前桌面 `dsh://open` 只能唤起窗口，精确会话跳转还需扩展接入。Harness API 处于稳定前阶段，适配器必须记录并测试兼容版本。

Tauri Windows 端使用 WebView2，macOS 端使用 WKWebView。透明窗口、穿透和后台动画需要分别验证，不根据框架选型直接承诺资源占用或帧率。

## 3. 方案比较与选择

| 方案 | 优点 | 代价 | 决定 |
| --- | --- | --- | --- |
| Swift、AppKit、SpriteKit | 可直接控制 macOS 原生窗口与动画 | Windows 需要另一套应用实现 | 不作为双平台主方案 |
| Tauri、Rust、TypeScript/Canvas | 共享大部分业务与渲染代码，适合常驻小工具 | 两个 WebView 和窗口系统需要分别验证 | 用户选择 |
| Electron、TypeScript/Canvas | 开发工具成熟，渲染环境比较统一 | 需要重点控制常驻资源与包体积 | 保留为验证失败后的候选，不自动切换 |

应用作为独立事件消费者运行；来源通过适配器主动转发。操作系统通知用作可选的最终展示渠道，不将读取通知中心、截屏或自动点击作为主接入方式。

## 4. 用户行为与第一版功能

1. 安装并启动桌宠，选择本仓库现有宠物或导入受支持的本地宠物包。
2. 设置页展示两个来源的版本、接入状态及已验证能力，用户安装对应适配配置。
3. 会话开始工作时切换工作动作；需要回答或审批时显示待处理提醒；明确结束、失败或中断时分别显示对应状态。
4. 气泡只显示来源、项目或会话名及短摘要。用户主动点击后打开原会话。
5. 通知列表按来源和会话保留未读项目；用户可标为已读、静音或隐藏桌宠。来源中的审批被处理后，关联待处理提醒自动解除。

后台提醒不主动抢键盘焦点。点击通知列表属于用户主动操作，可打开交互窗口；点击跳转才唤起来源应用。默认不播放声音，可单独开启。来源的既有通知是否关闭由用户决定，桌宠不自动修改其通知设置。

宠物可拖动、缩放并记忆位置。透明外缘点击应传给下层窗口，宠物及打开的交互面板接受点击。托盘菜单始终提供显示、隐藏、设置、通知列表、退出，避免鼠标穿透后无法恢复操作。

不包含：聊天客户端、直接批准和回答、任务启动或取消、多个宠物同时驻留、Live2D、自动补帧、远程同步、商城及养成系统。

## 5. 组件与进程

### 5.1 桌宠应用

Rust 主进程管理单实例、托盘、窗口、配置、通知存储、事件归一化和会话打开动作。事件接收与存储不依赖渲染窗口是否显示。应用退出时不再主动消费事件，转发器可在有界待发送区留存提醒。

宠物窗口只包围宠物和必要边距，避免全屏透明画布。设置与通知列表使用可正常聚焦的窗口。平台差异放在独立模块，不混入事件处理和动画状态逻辑。

### 5.2 原生通知转发器

安装包附带独立 Rust 命令 `pet-bridge`，Windows 为 `pet-bridge.exe`。它直接读取标准输入中的事件，完成格式检查与归一化、留存待发送事件，并尝试快速投递，不启动第二个 WebView。桌宠和转发器本身不要求用户额外安装 Python 或 Node；Harness 插件仍运行在 Harness 自己的 Node 环境。

Windows 调用时不弹出命令行窗口。脚本使用绝对安装路径与结构化标准输入，不把会话内容拼接进命令字符串。

### 5.3 本地事件入口与存储

应用只在 IPv4 loopback 监听随机端口，发现文件写入当前用户应用数据目录，记录端口及随机令牌。转发器读取发现文件后发送带令牌的请求；入口拒绝不匹配的令牌和浏览器跨源请求。应用只加载本地界面资源，外部会话链接经 Rust 校验后交给系统打开。

转发器先将重要事件原子写入用户目录中的待发送区，再尝试投递，桌宠确认事件持久化后才删除对应文件。断线、桌宠未启动时保留文件；文件监测、启动扫描和休眠恢复扫描负责补发。收件与补发共享 `eventId` 去重。适配器自身在产生事件前就已退出的情况无法靠转发器恢复。

默认待发送区上限 2,000 条、10 MiB、最长 24 小时，先淘汰过期项，再淘汰最旧项目；溢出写入诊断，下一次启动显示丢弃数量。历史记录最多 1,000 条、保留 7 天，用户可以清空。已处理事件 ID 的去重记录独立于可见历史裁剪，至少覆盖待发送区的有效期，避免历史压缩后将补发重试当成新提醒。配置用原子替换的 JSON，提醒日志由 Rust 单写入者管理并定期压缩；第一版不引入 SQL。

普通 Hook 转发路径在来源进程中只做快速留存与短时投递，不等待动画、窗口或用户点击。超时、无接收端和接收错误均不改变原任务或审批结果。Hook 标准输出遵循宿主事件协议，桥接诊断仅写标准错误或本地日志。

## 6. 统一事件与会话状态

事件包含协议版本、事件 ID、来源安装 ID、来源实例 ID、会话 ID、回合 ID（来源支持时）、上游事件 ID/序号（来源支持时）、发生时间、接收时间、事件种类及短摘要。可选上下文包括项目名称和目录；不传 API Key、完整提示词、工具参数或完整会话记录。

| 事件种类 | 解释与处理 |
| --- | --- |
| `turn_started` | 当前回合开始，设为工作中 |
| `attention_requested` | 有明确的回答或审批请求，保存请求 ID 和原因 |
| `attention_resolved` | 对应请求被回答、拒绝、取消或撤回，解除该请求的提醒 |
| `turn_ended` | 一轮已结束，结果可为正常结束、中断、失败或未知；不宣称业务目标达成 |
| `source_disconnected` | 仅用于具备可靠连接状态的适配器；无心跳的 Hook 来源不凭静默推断断线 |
| `source_snapshot` | 支持查询的来源返回当前快照，用于重连校正 |

以来源安装 ID、会话 ID 区分会话；每个会话同时维护当前回合状态、未解决请求和未读结束提醒。优先展示需要回答/审批、明确失败、未读结束、工作中、待机，同级按最近事件排序；通知列表始终保留全部会话。

使用上游序号、回合和请求 ID 处理因果关系。重复 `eventId` 不重复提醒；同一回合的迟到开始事件不能覆盖已确认的终态，旧回合不能清除新回合的待处理请求。适配器必须说明是否有可靠顺序与快照，缺少信息时保留未知状态，不用时间戳猜测成功。

桌宠重启后恢复未读历史，缓存的工作中状态标为未知；具备快照能力的适配器再校正。仅有 Hooks 的来源等待新事件更新，不把超过某个时长直接判为失败。启动补发先按会话归并已有待发送批次并重建状态，再展示尚未解决的请求与未读结束提醒，已经回答或撤回的历史请求不重新弹出气泡。

## 7. Codex 适配

主方案为用户级 Hooks，通过 `pet-bridge` 转发；同时测试 Codex 桌面应用和本地 CLI。接入只添加自有 Hook 条目，保留其他 Hook 与现有配置，并提供安装前备份及仅撤销自有条目的卸载方法。

| 目标能力 | 首选依据 | 验证要求 |
| --- | --- | --- |
| 开始工作 | `UserPromptSubmit` 等明确回合事件 | 桌面和 CLI 各用真实本地会话触发 |
| 待审批 | `PermissionRequest` | 请求出现、处理、取消后的状态都正确；适配器不返回批准或拒绝决定 |
| 一轮停止 | `Stop` | 标为回合结束，处理继续执行和重复停止，不推断任务成功 |
| 用户中断 | `Interrupt` | 显示中断，解除属于被中断回合的待处理状态 |
| 等待回答 | 用户输入工具或结构化事件 | 验证专用提问工具是否经过 Hook；不默认认为通用工具 Hook 覆盖所有路径 |
| 明确失败 | 结构化失败事件 | 不把模型回复文本或单个工具退出码直接当作全局失败 |

Hooks 无法提供必需能力时，先验证现有宿主是否允许通过其 App Server 连接观察目标会话，再选择补充适配方式。新建另一个 App Server 不视为接入现有桌面会话。当前文档不承诺能观察云端、其他主机或所有第三方 Codex 客户端。

Codex 会话跳转使用官方 `codex://threads/<thread-id>`，对 ID 编码并分别验证两平台。适配器记录会话来源；CLI 会话若无法通过已安装桌面应用定位，应显示明确的来源和可复制的会话 ID，不伪装为精确跳转成功。首版声明支持的桌面会话必须通过精确跳转验收。

用户需要在 Codex 自带的 Hook 信任界面完成来源要求的信任步骤。桌宠显示配置和检查结果，不绕过宿主信任机制。

兼容表记录产品版本、来源种类和每项能力。第一阶段必须确定桌面端开始、待处理、停止/中断和精确跳转的实现路径；关键能力缺失时不能将仅支持 CLI 宣称为完整 Codex 桌面接入，需修订方案。

## 8. DeepSeek Harness 适配

以外部 Cordis 插件观察公开事件，保持运行循环不变。主要使用 `agent/status` 和 `session/event` 中的 `turn/start`、`turn/end`、`approval/asked`、`approval/decided`。等待回答使用 `user-questions/request`；如果采用 waterfall 监听，转发后仍调用 `next()`，不领取或消费原请求。取消和回答完成都必须产生解除提醒的事件。

插件只转发状态变化与重要提醒，不转发 token 流或每个工具的全部输出。父会话、子代理使用各自身份；子代理噪声默认折叠进父会话，保留可定位的会话信息。

精确会话跳转优先通过同包 Host/Client 插件桥接到现有 `uiWorkspace.openSession`，然后唤起桌面窗口。此跨进程转发与隐藏窗口恢复需要先验证。若现有扩展点无法完成，则在 Harness 提供一个小范围的指定会话入口补丁并单独维护；具体方式由第一阶段验证确定，统一由桌宠的来源适配接口调用。

现有 `dsh://open` 只能作为出错时的“打开应用”操作，不能冒充“打开原会话”。两个平台都准确定位对应会话才算跳转完成。需记录插件支持的 Harness 版本；升级失配时显示接入异常，保留历史并停止错误的状态推断。

## 9. 动画和宠物包

首次加载解码图集并缓存，绘制时直接裁切已有图集区域，不逐帧读取文件、重新解码图片或驱动整个设置界面重渲染。使用 `requestAnimationFrame` 的时间戳计算时间轴；默认限制到 30 FPS，60 FPS 可选。卡顿后跳到正确时间位置，不逐帧补执行积压的计时回调。

角色姿态与画布绘制分开：现有 6 帧呼吸动作仍可按适合的周期播放，移动、拖动和轻微整体变换独立平滑绘制。提高画布刷新率不等于创造更多独立姿态；本版不自动生成补帧。

导入 Codex v1（1536×1872）和 v2（1536×2288）的透明 PNG/WebP，验证布局、尺寸、文件大小和解码结果。v2 的两行视线姿态按原方向定义解析，不作为普通连续动作播放。

应用内部格式使用显式的格子尺寸、动作帧列表、每帧时长和循环规则，解除固定 8 列动作容量。旧图集通过导入转换元数据复用，原包不被改写；以后更换更高帧数素材时播放器无需重构。鼠标跟随视线作为可选项，首版先保证原有状态动作正确。

桌宠隐藏或系统休眠时停止绘制；显示和恢复时按当前状态重新建立时间基准。未聚焦但可见时仍须达到设定目标，按实际 WebView 版本处理后台节流，不能仅以测试窗口聚焦时的帧率通过验收。

## 10. 双平台窗口与分发

窗口位置以逻辑坐标保存，显示器移除或缩放变化后限制在可见工作区。覆盖 macOS Retina 和 Windows 100%、150%、200% 缩放、多显示器不同缩放、休眠恢复、任务栏/Dock 工作区和跨屏拖动。

透明边缘穿透和角色点击以实际输入命中行为验收，不只检查视觉透明。必要时使用平台窗口 API；具体实现交由验证确定。普通模式不自动置于独占全屏应用上方；通知仍可进入历史。

macOS 提供应用包与 DMG，Windows 提供每用户安装的 NSIS 安装包及原生转发器。Windows 安装器检查并处理 WebView2 运行时，联网下载与失败重试应有明确提示；离线运行时打包另行扩展。

CI 分别构建 macOS arm64/x64 和 Windows x64；Windows 桌面运行验收必须在真实 Windows 环境完成，交叉编译不能替代窗口、输入和来源接入测试。当前只确认有本机 macOS 工作环境，Windows 测试环境应在实现首阶段落实。

个人测试包允许使用明确标识的未签名产物；公开发布前需准备 Apple 签名、公证及 Windows 签名配置，另行处理证书与发布权限。首版不因没有证书阻塞本地开发验证，也不将未签名测试包描述为正式发行版。

## 11. 模块划分建议

- `apps/desktop/`：Tauri 应用、Canvas 动画与设置界面。
- `crates/pet-core/`：事件协议、会话状态及包格式，保持无 UI 依赖。
- `crates/pet-bridge/`：原生通知转发命令。
- `integrations/codex/`：Hook 配置模板、接入和卸载说明、能力验证样例。
- `integrations/deepseek-harness/`：外部插件及跳转桥接；必要的宿主补丁单独标明。
- `pet-output/`：保留现有素材；应用构建只选入需要的发行资源。

模块的具体 workspace 配置、依赖版本、前端组件库和测试工具交给实施者选择。实现继续在当前分支，不擅自创建分支。

## 12. 实现阶段与验收

### 阶段一：双平台关键路径验证

验证透明窗口和输入行为、可见且未聚焦时的持续动画、Codex 桌面与 CLI 的事件覆盖、Harness 插件转发与精确会话跳转。记录宿主、OS、WebView 和依赖版本。Windows 环境未验证或精确跳转未完成时，不进入“两个平台均可用”的结论。

### 阶段二：可使用的第一版

完成状态管理、适配器安装与撤销、待发送区及历史、包导入、托盘和窗口记忆、设置、双平台安装包及来源兼容表。

### 验收矩阵

| 维度 | 通过标准 |
| --- | --- |
| 来源 | 两平台上分别用真实 Codex 桌面会话和 Harness 会话演示开始、待处理、回合结束/中断及跳转；失败只根据明确事件展示 |
| 会话跳转 | 两个来源同时至少 3 个会话，每条已支持的桌面通知打开准确来源和会话；失败显示可恢复错误 |
| 状态 | 重复、乱序、旧回合、请求撤回、并发来源不会把新状态覆盖为旧状态，不把缺失事件推断成成功 |
| 故障 | 桌宠关闭、重启、来源重连、休眠恢复后无原任务阻塞，待发送记录按规则补发且不重复提醒 |
| 动画 | 默认 30 FPS 模式，在指定参考机上连续 60 秒可见未聚焦播放，统计实际绘制间隔；至少 95% 间隔不超过 50 ms，另报长停顿及资源占用 |
| 通知延迟 | 从适配器收到宿主事件到桌宠可见状态更新，正常运行时 P95 小于 500 ms；离线补发单独统计 |
| 资源 | 两平台分别记录待机、动画、隐藏三个状态各 5 分钟的 CPU、进程树内存及后台唤醒；隐藏时停止绘制，性能预算在阶段一实测后锁定 |
| 安装 | 干净用户配置可安装、配置来源、撤销接入并卸载；保留用户原有 Hook、配置与宠物素材 |

纯状态逻辑和协议用可重放事件测试验证；适配器用版本化样例验证；原生窗口和深链使用真实双平台集成测试。用户要求禁止循环中查询 SQL，第一版使用文件存储，未来更换存储时也必须遵守该约定。

现有估算为验证原型 5～8 人日、日常可用版 15～25 人日，不含素材重制、远程环境、公开发布证书办理。Codex 桌面事件补充接入和 Harness 会话入口的验证结果可能改变估算，阶段一结束后重新评估。

## 13. 交付与下一步

本阶段交付设计及独立审阅结果。用户确认默认平台范围、首版功能和整体架构后，再编写实现计划。实现计划首先解决阶段一的不确定项，不先铺完整应用再验证来源和平台关键路径。

2026-11-11，独立实施者已按能否据此制定实现计划进行只读审阅，结果为“没有重要遗留问题”。该审阅针对设计完整性，不替代阶段一的运行验证。
